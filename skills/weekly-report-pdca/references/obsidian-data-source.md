# Obsidian 数据源：周报聚合规范

从 Obsidian 知识库 `1_日志/` 聚合本周日志生成周报。本文档沿用 obsidian-kb-update 旧版周报逻辑（2026-07-10 版 Step 9），与本 skill 的 PDCA 编排结合使用。

## 1. 确定周范围

- 计算当前 ISO 周编号（周一至周日），生成 7 天日期列表
- 目标文件：`1_日志/YYYY/YYYY-Www.md`（Markdown）与 `1_日志/YYYY/YYYY-Www.html`（HTML，可选）
- 周报已存在：询问用户覆盖还是跳过
- 跨月周（如 6 月底 + 7 月初）：放在日志数量更多的年份目录
- 日志缺失某天：跳过，覆盖日期列表中不包含该天

## 2. 收集数据（遍历 7 篇日志）

对每篇日志 `1_日志/YYYY/YYYY-MM-DD.md`：

```
├── 存在 → 读取
│   ├── # 工作记录 → 按 [[项目名]] 拆分，收集到 project_bucket
│   ├── # 英语学习 → 检测 [x] 数量 → 打卡计数
│   ├── # 健身记录 → 提取关键词 → 天数计数
│   ├── # 生活记录 → 提取有实质内容的行
│   ├── # 所思所想 → 提取首条引文块 "> ..." 或长句
│   └── wikilinks（非项目的） → 学习/技术笔记
└── 不存在 → 跳过，覆盖日期列表中不包含该天
```

- 工作记录段落以 `## [[项目名]]` 或 `- [[项目名]] 内容` 形式提及项目（兼容 frontmatter `项目` 字段）
- 项目与任务的当前状态可参考 `4_项目/{项目名}.md`（pm-project）与 `4_项目/{项目名}_tasks/`（pm-task）的 frontmatter（status/priority/due/progress），用于丰富"Check/Act"证据
- `4_项目/` 下文件只读，本 skill 不写入

## 3. 周报 Frontmatter 规范

```yaml
---
日期: YYYY-Www       # ISO 周编号，如 "2026-W28"
类型: 周报
周次: 28
tags: []             # 本周日志 tags 去重
项目: []             # 本周涉及的项目名列表
覆盖日期:            # 本周 7 天日期列表（周一至周日，缺失天不包含）
  - YYYY-MM-DD
总结:                # 本周一句话概括
---
```

## 4. 周报正文结构（Markdown）

```markdown
# 本周摘要
一句话概括 + 关键数字表格（项目数/英语打卡/健身天数/新增笔记）

# 项目进展
## [[项目A]]
- 具体进展按日期归纳
## [[项目B]]
- ...

# 学习进度
## 英语（打卡 X/7 天）
## 技术（本周新增笔记列表）

# 生活摘要
健身/生活事件简要

# 所思所想精选
> 本周有启发的思考摘录

# 下周计划
- [ ] 手动填写（或按 PDCA 的 Act 归纳）

# 本周日志
- [[周一日志]]
- [[周二日志]]
- ...
```

## 5. 聚合生成规则

- `tags` → 7 天日志 tags 去重合并
- `项目` → 工作记录 wikilinks 去重
- `总结` → 项目进展 + 学习进度各取 1 句拼接
- 关键数字表 → 涉及项目数 / 英语打卡 / 健身天数 / 新增笔记
- 项目进展 → project_bucket 按项目名聚合，按天归纳
- 学习进度 → 英语打卡 + 本周新增 wikilinks 列表
- 生活摘要 → 健身天数 + 生活事件
- 所思所想精选 → 引文摘录
- 下周计划 → 预置空白 [ ] 区域

## 6. 边界情况

- 本周日志为 0 篇：不生成，报告"本周无日志"
- 周报已存在：询问是覆盖还是跳过
- 跨月周（如 6 月底 + 7 月初）：放在日志数量更多的年份目录
- 日志缺失某天：覆盖日期列表中不包含该天
- **生成时序（审批流）**：先输出 Markdown 供用户审批修改；用户明确同意后，再基于定稿 Markdown 生成 HTML。HTML 内容必须与已审批的 Markdown 一致，不得在 HTML 中新增 Markdown 中没有的事实或表述
- Markdown 用于知识库归档与 wikilink 体系，HTML 用于网页交付；两者内容一致
