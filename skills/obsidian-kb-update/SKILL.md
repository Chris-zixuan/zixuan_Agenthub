# Obsidian 知识库更新

知识库维护管家。写完日志后一键完成增量维护，支持知识发现。项目与任务管理由 Project Manager 插件（obsidian-pm）负责，本 skill 聚焦日志↔项目的关联与索引，只读 pm 数据、不写 `4_项目/` 下任何文件。

## 前置条件

1. 确认知识库根目录（默认 `C:\Users\yangz\Nutstore\1\Obsidian\我的知识库`）
2. 读取 [references/kb-spec.md](references/kb-spec.md) 获取完整规范（含 Project Manager 项目结构、frontmatter 字段、Dataview 模板）

## 工作流

基础更新按顺序执行以下 7 步，每步完成后向用户报告结果。Step 8 为自动附带检查。Step 9 为独立触发功能。

### Step 1: 识别目标日志

- 确定要处理的日志：今天或用户指定的日期
- 文件路径：`1_日志/YYYY/YYYY-MM-DD.md`
- 读取全文，提取 frontmatter 和正文

### Step 2: Frontmatter 补全

检查并补全以下字段（仅补空，不改已有值）：

| 字段 | 自动推断规则 |
|------|------------|
| `项目` | 从正文 `# 工作记录` 段落的 `[[xxx]]` wikilink 提取，与 `4_项目/` 下的 pm-project 项目名对齐校验，去重后填入列表 |
| `tags` | 根据 `项目` 内容和正文关键词匹配领域标签词表（见 kb-spec.md），去重后填入嵌套标签。已有标签不覆盖 |
| `总结` | 如果为空，通读全文（工作记录 + 生活记录 + 健身 + 所思所想等所有段落），提取最有代表性的一两件事，精简为一句话 |
| `日期` | 如果为空，从文件名提取 |
| `类型` | 如果为空，设为 `每日记录` |

**项目名校验**：日志中 `[[项目名]]` 提及的项目，若不在 `4_项目/` 的 pm-project 列表中：
- 报告 ⚠️ "项目 X 不在 Project Manager 中"
- 提示用户确认是否在 pm 插件中新建项目，不自动创建

**领域标签推断逻辑**（按关键词匹配，写入 tags 平铺标签或嵌套标签，详见 kb-spec.md）：

**工作领域**：
- 提到 标定/手眼/内外参/张正友 → 标定
- 提到 抓取/机器人/上下料/定位 → 定位抓取
- 提到 点云/3D匹配/3D定位/深度 → 3D视觉
- 提到 焊缝/铸造/缺陷/检测 → 缺陷检测
- 提到 算法/优化/梯度/SVD → 算法
- 提到 Claude/Agent/Skill/LLM/AI/LangChain → AI
- 提到 VM/脚本/C#/IDE/环境 → 开发工具
- 提到 远程/代理/服务器/网络 → 网络运维

**个人/生活**：
- 提到 Obsidian/知识库/笔记 → Obsidian
- 提到 背单词/墨墨/英语/口语/English → 英语学习
- 提到 简历/面试/跳槽/离职/华睿/offer → 职业/跳槽
- 提到 健身/跑步/深蹲/体重/有氧 → 健身
- 提到 尤佳欣/约会/吵架 → 生活

补全后用 Edit 工具写回文件。

### Step 3: 工作记录 pm 融合

对日志 `# 工作记录` 中提及的每个 pm 项目，读取其任务状态并向用户汇报（**只读，不修改 `4_项目/` 下任何文件**）：

1. 定位项目主文件：`4_项目/{项目名}.md`，读取 `id` 和 `taskIds`
2. 读取 `4_项目/{项目名}_tasks/` 下任务文件的 `status`、`priority`、`due`、`progress`
3. 汇报格式（纯文本，不写文件）：

```
📋 项目任务快照 — {项目名}

进行中: 撰写SOP (in-progress, 截止 08-13, 0%)
待开始: 软件功能测试 (todo, 无截止)
已完成: 新版本功能开发 (done)
到期提醒: 撰写SOP 已到期
```

4. 若项目不在 pm 中（旧 MOC 归档项目或新建未登记），报告"该项目不在 Project Manager 中"，跳过快照

**边界**：
- pm 任务文件缺失或损坏 → 报告"无法读取任务状态"，继续后续步骤
- 日志无 `# 工作记录` 段落 → 跳过本步

### Step 4: 同步项目进度

对日志中 `[[项目名]]` 提及的每个项目：

1. 确认项目为 pm 项目（`4_项目/{项目名}.md` 存在且 `pm-project: true`）
2. 检查 `4_项目/{项目名}_tasks/_others/进度记录.md` 是否存在且含 Dataview 查询代码
3. 若存在 → 报告 "进度记录由 Dataview 自动查询，无需人工写入"，不修改任何文件
4. 若缺失 → 报告 ⚠️ "进度记录文件缺失"，提示用户检查项目结构，不自动创建
5. 旧 MOC 归档项目（`3_工作/项目管理/1_归档项目/`）：不写进度，仅报告"已归档项目，不更新进度"

### Step 5: 检查 Wikilinks

1. 提取正文中所有 `[[xxx]]` wikilink
2. 用 `find` 检查每个链接对应的 .md 文件是否存在
3. 对不存在的链接，报告给用户（标注 ⚠️）
4. 不自动创建缺失文件

### Step 6: 更新 index.md

1. 读取 `index.md`
2. 检查日志中提及的笔记是否已在 index.md 中：
   - 对每个 wikilink 目标，搜索 index.md 中是否出现同名链接
   - 未收录的笔记，根据其所在目录和内容归入 index.md 对应分类
3. 如果日志本身有特别有价值的总结，可考虑在 index.md 的 `待归档` 或相关段落备注

**index.md 分类归属规则**（详见 kb-spec.md）：

- `3_工作/工作知识库/5_理论知识/标定理论/` → 第 1.2 节 标定
- `3_工作/工作知识库/5_理论知识/定位与抓取/` → 第 1.1 节 理论基础
- `3_工作/工作知识库/5_理论知识/算法与数学/` → 第 1.4 节 算法原理
- `3_工作/工作知识库/5_理论知识/Opencv/` → 第 1.3 节 算子参考
- `3_工作/工作知识库/5_理论知识/PCL/` → 第 1.5 节 3D点云
- `3_工作/工作知识库/1_软件产品/` → 第 1.3 节 算子参考 / 第 1.6 节 实战经验
- `3_工作/工作知识库/3_经验笔记/` → 第 1.6 节 实战经验
- `2_个人/经验/视觉算法/` → 第 1.6 节 实战经验
- `4_项目/`（pm-project + `_tasks/` 子文件） → 第 2 节 项目
- `3_工作/项目管理/1_归档项目/`（旧 MOC 归档） → 第 2.5 节 已归档
- `2_个人/经验/AI/` → 第 3 节 AI与Agent
- `2_个人/经验/开发工具/` → 第 4 节 开发工具
- `2_个人/生活/` → 第 5.1 节 生活 / 第 5.4 节 人生思考
- `2_个人/跳槽准备中/` → 第 5.3 节 职业发展 / 第 5.5 节 跳槽准备中
- `3_工作/英语学习/` → 第 5.1 节 生活
- `0_Inbox/Clippings/` → 第 6 节 待归档

### Step 7: 维护主题 MOC

1. 读取 `9_系统/MOC/主题索引.md`（如果不存在则跳过本步）
2. 如果日志的 `tags` 包含一级标签，检查该标签下是否有新的知识笔记链接需要补充
3. 从日志的 wikilink 中找到属于该标签的笔记，补充到 MOC 的对应标签段落

### Step 8: 项目活跃度检查

每次知识库更新时顺带检查所有 pm 项目活跃度，纯诊断不修改文件。

**8.1 扫描范围**

- `4_项目/` 下所有 `pm-project: true` 的 .md 文件（obsidian-pm 项目）

**8.2 状态判定**

```
for each pm 项目:
    读取 4_项目/{项目名}.md 的 updatedAt
    // 通过 Dataview 查询 1_日志/ 中提及该项目的日记
    // 取最新一篇日记的日期作为"日志活动日期"
    if 无匹配日记 and updatedAt 久远 → 报告"无法判定活跃度，建议在 pm 中确认"
    else:
        最后活动日期 = max(日志提及日期, 项目 updatedAt)
        if 最后活动日期 > 30 天 → 🔴 严重停滞
        elif > 14 天 → 🟡 需关注
        else → ✅ 正常
```

**8.3 输出格式**

纯文本输出，不写文件：

```
📊 项目活跃度检查 — YYYY-MM-DD

✅ 正常 (≤14天): 延锋座椅检测项目 (2天前)
🟡 关注 (15-30天): 大3D项目支持 (22天前)
🔴 停滞 (>30天): 柔性点检框架项目 (49天前)
💤 无法判定: 项目X（无日志提及）
```

**8.4 边界情况**
- pm 项目无匹配日记 → 报告"无法判定活跃度，建议在 pm 中确认"
- 全部项目正常 → 简化输出为"✅ 所有项目活跃度正常"
- 归档项目（`1_归档项目/`）：不纳入检查

### Step 9: 交叉引用发现

独立触发功能，建议但不自动修改。触发词："交叉引用"、"知识发现"。

**9.1 提取技术关键词**

从日志 `# 工作记录` 中提及的项目出发，读取 `4_项目/{项目名}_tasks/_others/项目总览.md` 的 `## 方案记录` 段落，提取技术关键词（如"手眼标定"、"SVD"、"3D匹配"、"点云分割"）。

**9.2 搜索理论知识库**

在 `3_工作/工作知识库/5_理论知识/` 下搜索匹配的目录或笔记。

**9.3 对比现有链接**

对比项目总览 `## 相关文档` 中的已有链接，过滤已存在的。

**9.4 输出格式**

```
🔗 交叉引用建议

[[延锋座椅检测项目|延锋座椅检测]]：
  → 提到"深度图处理" → [[深度图处理技巧]]（建议链接）
  → 提到"SVM分类" → [[SVM原理与应用]]（建议链接）
```

只建议，不自动添加链接。

```
✅ Frontmatter 补全：项目=[xxx, yyy]，tags=[标定, 缺陷检测]，总结="..."
📋 任务快照：延锋座椅检测项目（进行中 2 / 待开始 1 / 已完成 1）
📝 项目进度：由 Dataview 自动查询，无需写入
⚠️ 失效链接：[[不存在的笔记]]
⚠️ 项目名校验：项目X 不在 Project Manager 中
📝 index.md：新增 N 条索引
📝 主题 MOC：更新 N 个标签（如该文件存在）
📊 项目活跃度检查：（如需检查，见 Step 8）
```

|------|--------|---------|
| 项目活跃度检查 | 自动随更新执行 | Step 8 |
| 交叉引用发现 | "交叉引用"、"知识发现" | Step 9 |
| 知识库体检 | "知识库体检"、"健康检查" | 独立功能（待实现） |

周报生成已移交独立 skill，本 skill 不再响应"周报"触发词。

## 边界情况

- **用户指定日期**：如 "更新 6 月 1 日的知识库"，处理 `1_日志/2026/2026-06-01.md`
- **日志不存在**：告知用户指定日期的日志不存在
- **Frontmatter 已完整**：跳过 Step 2，报告"无需补全"
- **无 wikilink**：跳过 Step 3 和 4，报告"正文中无笔记链接"
- **项目不在 pm 中**：Step 3 报告快照跳过，Step 4 报告不写进度，提示用户在 pm 中确认
- **pm 任务文件缺失**：报告"无法读取任务状态"，继续后续步骤
- **项目已归档（1_归档项目/）**：不写进度、不纳入活跃度检查
- **批量更新**：如用户说"更新最近一周的知识库"，逐日执行 Step 1-7（不含 8-9）
- **主题索引不存在**：Step 7 跳过，不报错
- **日期格式**：`日期` 字段统一为无引号格式 `YYYY-MM-DD`，读取时兼容两种格式

## 注意事项

- 只修改 frontmatter 和索引文件（index.md、MOC），不修改日志正文
- **`4_项目/` 下所有文件（pm-project / pm-task / Archive）完全由插件管控，skill 只读不写**
- 进度记录由 Dataview 自动查询拉取，skill 不手动写入
- 保留原始图片引用格式，不修改任何 `![[]]` 或 `![]()` 引用
- LaTeX 行内公式 `$` 与内容间不允许有空格
- wikilink 使用短名格式 `[[笔记名]]`
- 新增 index.md 条目时保持现有格式和缩进风格
- 任务管理在 Project Manager 插件中操作，skill 不创建/修改任务
