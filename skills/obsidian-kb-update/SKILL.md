# Obsidian 知识库更新

知识库维护管家。写完日志后一键完成增量维护，支持知识发现。项目与任务管理由 Project Manager 插件（obsidian-pm）负责，本 skill 聚焦日志↔项目的关联与索引，只读 pm 数据、不写 `4_项目/` 下任何插件管控文件（`_others/` 手动文档除外，仅建议不自动写）。

## 前置条件

1. **确定知识库根目录**（双机部署，运行时探测）：
   - Mac 默认：`/Users/yangzixuan/Documents/Obsidian/我的知识库`
   - Windows 默认：`C:\Users\yangz\Nutstore\1\Obsidian\我的知识库`
   - 探测顺序：① 运行环境 OS 判断（`uname` / `$OSTYPE`）→ ② 检查默认路径是否存在 → ③ 均不存在时询问用户
2. 读取 [references/kb-spec.md](references/kb-spec.md) 获取完整规范（含 Project Manager 项目结构、frontmatter 字段、Dataview 模板、index.md 归属规则）
3. 命令适配：Mac/Linux 用 `find`/`grep`/`rg`；Windows 用 `dir`/`findstr` 或 PowerShell 等价命令

## 工作流

基础更新按顺序执行以下 8 步，每步完成后向用户报告结果。Step 9 为自动附带检查，Step 10 为总索引维护，Step 11 为独立触发功能。

### Step 1: 识别目标日志

- 确定要处理的日志：今天或用户指定的日期
- 文件路径：`1_日志/YYYY/YYYY-MM-DD.md`
- 读取全文，提取 frontmatter 和正文

### Step 2: Frontmatter 补全

检查并补全以下字段（仅补空，不改已有值）：

| 字段 | 自动推断规则 |
|------|------------|
| `项目` | 从 `# 工作记录` 段落下的 `## [[xxx]]` 二级标题及列表中的 wikilink 提取，与 `4_项目/{项目名}/{项目名}.md` 的 pm-project 项目名对齐校验，去重后填入列表 |
| `tags` | 根据 `项目` 内容和正文关键词匹配领域标签词表（见 kb-spec.md），去重后填入。每日记录允许工作领域 + 个人/生活两套词表；已有标签不覆盖 |
| `总结` | 如果为空，通读全文（工作记录 + 生活记录 + 健身 + 所思所想等所有段落），提取最有代表性的一两件事，精简为一句话 |
| `日期` | 如果为空，从文件名提取，格式 `YYYY-MM-DD` 无引号 |
| `类型` | 如果为空，设为 `每日记录` |

**项目名校验**：日志 `# 工作记录` 中 `[[项目名]]` 提及的项目，若不存在 `4_项目/{项目名}/{项目名}.md`（pm-project）：
- 报告 ⚠️ "项目 X 不在 Project Manager 中"
- 提示用户确认是否在 pm 插件中新建项目，不自动创建

**领域标签推断逻辑**（按关键词匹配，写入 tags，详见 kb-spec.md 词表）：

**工作领域**：
- 提到 标定/手眼/内外参/张正友 → 标定
- 提到 抓取/机器人/上下料/定位 → 定位抓取
- 提到 点云/3D匹配/3D定位/深度 → 3D视觉
- 提到 焊缝/铸造/缺陷/检测 → 缺陷检测
- 提到 算法/优化/梯度/SVD → 算法

- 提到 VM/脚本/C#/IDE/环境 → 开发工具
- 提到 远程/代理/服务器/网络 → 网络运维

**个人/生活**：
- 提到 Obsidian/知识库/笔记 → Obsidian

- 提到 尤佳欣/约会/吵架 → 生活

补全后用 Edit 工具写回文件。

### Step 3: 工作记录 pm 融合

对日志 `# 工作记录` 中提及的每个 pm 项目，读取其任务状态并向用户汇报（**只读，不修改 `4_项目/` 下任何插件管控文件**）：

1. 定位项目主文件：`4_项目/{项目名}/{项目名}.md`，读取 frontmatter 的 `taskIds`（wikilink 列表）
2. 读取 `4_项目/{项目名}/_tasks/` 下任务文件的 `status`、`priority`、`due`、`progress`
3. 汇报格式（纯文本，不写文件）：

```
📋 项目任务快照 — {项目名}

进行中: 撰写SOP (in-progress, 截止 09-11, 0%)
待开始: 软件功能测试 (todo, 无截止)
已完成: 新版本功能开发 (done)
到期提醒: 撰写SOP 已到期
```

4. 若项目不在 pm 中（旧 MOC 归档项目或新建未登记），报告"该项目不在 Project Manager 中"，跳过快照

**边界**：
- pm 任务文件缺失或损坏 → 报告"无法读取任务状态"，继续后续步骤
- 日志无 `# 工作记录` 段落 → 跳过本步

### Step 4: 同步项目进度

对日志中 `[[项目名]]` 提及的每个项目：

1. 确认项目为 pm 项目（`4_项目/{项目名}/{项目名}.md` 存在且 `pm-project: true`）
2. 检查 `4_项目/{项目名}/_tasks/_others/进度记录.md` 是否存在且含 Dataview 查询代码
3. 若存在 → 报告 "进度记录由 Dataview 自动查询，无需人工写入"，不修改任何文件
4. 若缺失 → 报告 ⚠️ "进度记录文件缺失"，提示用户检查项目结构，不自动创建
5. 旧 MOC 归档项目（`3_工作/项目管理/1_归档项目/`）：不写进度，仅报告"已归档项目，不更新进度"

### Step 5: 检查 Wikilinks

1. 提取正文中所有 `[[xxx]]` wikilink
2. 检查每个链接对应的 .md 文件是否存在于知识库（Obsidian 短名解析，全库文件名唯一即可命中）
3. 对不存在的链接，报告给用户（标注 ⚠️）
4. 不自动创建缺失文件

1. 读取根目录 `index.md`
2. 检查日志中提及的笔记是否已在 index.md 中：
   - 对每个 wikilink 目标，搜索 index.md 中是否出现同名链接
   - 未收录的笔记，先判断是否满足"长期重要/高频"收录门槛，再按下方归属规则归入对应板块
3. 满足门槛的新笔记用 Edit 插入对应板块，保持现有格式（`- [[笔记名]] 描述` 或 `- [[笔记名]] — 描述`）与缩进风格

### Step 8: 项目活跃度检查

每次知识库更新时顺带检查所有 pm 项目活跃度，纯诊断不修改文件。

**8.1 扫描范围**

- `4_项目/{项目名}/{项目名}.md` 且 `pm-project: true` 的项目（obsidian-pm 项目）

**8.2 状态判定**

```
for each pm 项目:
    读取 4_项目/{项目名}/{项目名}.md 的 updatedAt
    // 在 1_日志/ 中搜索提及该项目的日记（正文 [[项目名]] 或 frontmatter 项目 字段）
    // 取最新一篇日记的日期作为"日志活动日期"
    if 无匹配日记 and updatedAt 久远 → 报告"无法判定活跃度，建议在 pm 中确认"
    else:
        最后活动日期 = max(日志提及日期, 项目 updatedAt)
        if 最后活动日期 > 30 天 → 🔴 严重停滞
        elif > 14 天 → 🟡 需关注
        else → ✅ 正常
```

**8.3 输出格式**

纯文本输出，不写文件：

```
📊 项目活跃度检查 — YYYY-MM-DD

✅ 正常 (≤14天): 延锋座椅检测项目 (2天前)
🟡 关注 (15-30天): 大3D项目支持 (22天前)
🔴 停滞 (>30天): 柔性点检框架项目 (49天前)
💤 无法判定: 项目X（无日志提及）
```

**8.4 边界情况**
- pm 项目无匹配日记 → 报告"无法判定活跃度，建议在 pm 中确认"
- 全部项目正常 → 简化输出为"✅ 所有项目活跃度正常"
- 归档项目（`3_工作/项目管理/1_归档项目/`）：不纳入检查

**9.3 对比现有链接**

**9.4 输出格式**

[[延锋座椅检测项目|延锋座椅检测]]：
  → 提到"深度图处理" → [[深度图处理技巧]]（建议链接）

### Step 10: 维护知识库总索引

`9_系统/MOC/知识库总索引.md` 是 Agent 使用的全量导航（区别于用户精选入口 index.md）。独立触发词："更新总索引"、"同步总索引"。

**10.1 文件存在时**

1. 读取总索引 frontmatter 中的 `最后更新` 日期
2. 判断是否需要更新：距上次更新超过 7 天，或用户明确要求，或本次知识库更新产生了目录级变化（新增/删除项目目录、新增归档、新笔记归类）→ 执行更新；否则报告"总索引 X 天前已更新，未超期"
3. 更新内容：目录树统计（各一级目录笔记数）、pm 项目清单（含状态）、归档项目清单、Clippings 状态、系统文件清单
4. 更新后写回 `最后更新: YYYY-MM-DD`

**10.2 文件不存在时**

报告 ⚠️ "知识库总索引不存在"，说明 AGENTS.md 与 index.md 均引用了该文件（悬空链接），询问用户是否由 skill 创建首版（需全库扫描，一次性生成全量结构索引）。用户确认后：

1. 扫描全部一级目录及子目录，统计 .md 文件数
2. 生成结构：目录总览（树+统计）、pm 活跃项目清单、归档项目清单、主题标签聚合（可整合原规划的"主题索引"功能：按 tags 一级词表聚合知识笔记链接）、系统文件清单（9_系统/MOC、Dashboard、模板、看板）
3. frontmatter 写入 `类型: MOC`、`总结`、`最后更新`，正文开头注明"Agent 全量导航，每周更新"
4. 创建后在变更摘要中报告

**10.3 边界情况**
- 用户未确认创建 → 跳过，仅在变更摘要中保留 ⚠️ 提示
- 主题索引.md 与总索引的关系：若用户选择将主题聚合并入总索引，则 Step 7 自动改读总索引的主题段落

## 边界情况

- **用户指定日期**：如 "更新 6 月 1 日的知识库"，处理 `1_日志/2026/2026-06-01.md`
- **日志不存在**：告知用户指定日期的日志不存在
- **Frontmatter 已完整**：跳过 Step 2，报告"无需补全"
- **无 wikilink**：跳过 Step 3 和 4，报告"正文中无笔记链接"
- **项目不在 pm 中**：Step 3 报告快照跳过，Step 4 报告不写进度，提示用户在 pm 中确认
- **pm 任务文件缺失**：报告"无法读取任务状态"，继续后续步骤
- **项目已归档（1_归档项目/）**：不写进度、不纳入活跃度检查
- **批量更新**：如用户说"更新最近一周的知识库"，逐日执行 Step 1-7（不含 8-10）
- **主题索引不存在**：Step 7 跳过，不报错
- **总索引不存在**：Step 10 报告并询问，不自动创建
- **日期格式**：`日期` 字段统一为无引号格式 `YYYY-MM-DD`，读取时兼容两种格式
- **跨机运行**：路径按前置条件探测规则确定；skill 真身托管于 GitHub `Chris-zixuan/zixuan_Agenthub`，两机克隆目录不同（Mac: `/Users/yangzixuan/个人项目/zixuan_Agenthub`，Windows: `D:/个人项目/zixuan_Agenthub`），通过 npx skills 分发
