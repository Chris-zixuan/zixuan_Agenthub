# 运维层 · 知识库增量维护

日志写完后的一键增量维护，把**当天日志**与**库内项目 / 索引**之间的增量关系补齐。

> 触发词：更新知识库、更新我的知识库、同步知识库、交叉引用、知识发现、项目活跃度检查、健康看板扫描。
> 库规范以 `9_系统/协作约定.md` 为准；CLI 用法见 `cli-reference.md`；库结构映射见 `vault-spec.md`。

---

## 定位与边界

### 做什么

把日志写完后遗留的**关系缺口**补上：frontmatter 缺字段、日志提到的项目没登记、链接断了、该进 index 的笔记没进。

### 🚫 不做什么（本层最容易出错的地方）

| 不做 | 原因 |
|---|---|
| **不维护 `9_系统/MOC/知识库总索引.md`** | 已改为 Dataview 动态生成，**免维护**。它没有 `最后更新` 字段，人工写入会被下次渲染覆盖 |
| **不维护 `9_系统/MOC/主题索引.md`** | 同上，Dataview 动态生成，免维护 |
| **不写 `4_项目/` 下任何 pm 管控文件** | `协作约定.md` §1.1 红线之一，插件独占 |
| **不修改日志正文** | 只补 frontmatter |
| **不创建 / 修改 pm 任务** | 任务增删改一律由用户在插件界面完成 |
| **不处理周报** | 已移交独立 skill `weekly-report-pdca` |

> ⚠️ **历史教训（务必牢记）**：本层旧版本曾包含「维护主题 MOC」（Step 7）与「维护知识库总索引」（Step 10）两步。但在 2026-09-12 这两个索引改为 Dataview 动态生成后，这两步就成了死逻辑 —— 旧版还要去读一个根本不存在的 `最后更新` 字段来判断"是否超期 7 天"。**不要去"维护"它们。**

## 基础更新流程

触发："更新知识库" / "更新我的知识库" / "同步知识库"。按顺序执行，每步完成后向用户报告结果。

### Step 1 · 识别目标日志

- 确定要处理的日志：今天，或用户指定的日期
- 路径：`1_日志/YYYY/YYYY-MM-DD.md`
- 读全文，提取 frontmatter 与正文

### Step 2 · Frontmatter 补全

**仅补空，不改已有值。** 字段清单：

| 字段 | 自动推断规则 |
|---|---|
| `项目` | 从 `# 工作记录` 段落下的 `## [[xxx]]` 二级标题及列表中的 wikilink 提取，与 `4_项目/{项目名}/{项目名}.md` 的 pm 项目名对齐校验，去重后填入列表 |
| `tags` | 按下方关键词提示表匹配，**标签名本身以 `协作约定.md` §4 词表为准**；去重后填入。每日记录允许技术域 + 个人域两套；已有标签不覆盖 |
| `总结` | 为空时通读全文（工作记录 + 生活记录 + 健身 + 所思所想等**所有**段落），提取最有代表性的一两件事，精简为一句话 |
| `日期` | 为空时从文件名提取，格式 `YYYY-MM-DD`，无引号 |
| `类型` | 为空时设为 `每日记录` |

**关键词 → 标签 推断提示**（仅作匹配线索；**标签名以协作约定 §4 为准**）：

*技术域（9 个）*

| 标签 | 关键词线索 |
|---|---|
| `3D视觉` | 点云 / 3D匹配 / 3D定位 / 深度图 |
| `定位抓取` | 抓取 / 机器人 / 上下料 / 定位 |
| `标定` | 标定 / 手眼 / 内外参 / 张正友 |
| `缺陷检测` | 焊缝 / 铸造 / 缺陷 / 检测 |
| `算法` | 算法 / 优化 / 梯度 / SVD |
| `AI` | Claude / Agent / Skill / LLM / LangChain |
| `开发工具` | VM / 脚本 / C# / IDE / 环境 |
| `网络运维` | 远程 / 代理 / 服务器 / 网络 |
| `Obsidian` | Obsidian / 知识库 / 笔记 |

*个人域（5 个，仅每日记录使用）*

| 标签 | 关键词线索 |
|---|---|
| `生活` | 生活记录 / 家庭 / 关系 / 健身 / 读书 / 感悟（二级：`生活/家庭`、`生活/健身`） |
| `成长` | 人生感悟 / 职业规划 / 自我提升（二级：`成长/职业规划`） |
| `求职` | 简历 / 面试 / 行业调研 / 跳槽决策（二级：`求职/简历`、`求职/面试`） |
| `健康` | 身体状况 / 就医 / 作息 |
| `英语` | 英语学习 / 背单词 / 口语 |

> ⚠️ **禁用旧标签**：`职业/跳槽`、`英语学习`、`健身`（一级）已由 `协作约定.md` §4.4 重映射为 `求职`、`英语`、`生活/健身`。
> 项目名**不得**当标签用（由 `项目` 字段承载）。`类型` / `状态` 也不进 tags。

补全后用 Edit 写回文件。

**项目名校验**：日志 `# 工作记录` 中提及的项目若不存在 `4_项目/{项目名}/{项目名}.md`：

- 报告 ⚠️「项目 X 不在 Project Manager 中」
- 提示用户确认是否在 pm 插件中新建，**不自动创建**

### Step 3 · 项目关联与任务快照（只读）

对日志中提及的每个 pm 项目：

1. 定位主文件 `4_项目/{项目名}/{项目名}.md`，读 frontmatter 的 `taskIds`（wikilink 列表）
2. 读 `4_项目/{项目名}/_tasks/` 下任务文件的 `status`、`priority`、`due`、`progress`
3. 汇报（纯文本，不写文件）：

```
📋 项目任务快照 — {项目名}

进行中: 撰写SOP (in-progress, 截止 09-11, 0%)
待开始: 软件功能测试 (todo, 无截止)
已完成: 新版本功能开发 (done)
到期提醒: 撰写SOP 已到期
```

4. **检查进度记录结构**：确认 `_tasks/_others/进度记录.md` 存在且含 Dataview 查询代码
   - 存在 → 报告「进度由 Dataview 自动查询，无需人工写入」，**不修改任何文件**
   - 缺失 → 报告 ⚠️「进度记录文件缺失」，提示用户检查项目结构，**不自动创建**
5. 旧 MOC 归档项目（`3_工作/项目管理/1_归档项目/`）→ 报告「已归档项目，不更新进度」
6. 项目不在 pm 中（旧 MOC 归档或新建未登记）→ 报告「该项目不在 Project Manager 中」，跳过快照

**边界**：pm 任务文件缺失或损坏 → 报告「无法读取任务状态」，继续后续步骤；日志无 `# 工作记录` 段落 → 跳过本步。

### Step 4 · 链接健康检查

**优先用 CLI**（Obsidian 自有解析口径，能正确处理 `[[名|别名]]`、`[[名#标题]]`、相对路径，比手写正则准）：

```bash
obsidian unresolved              # 全库未解析链接
```

1. 提取日志正文中的 wikilink 目标
2. 取全库未解析清单，交叉比对，找出**本日志涉及**的未解析链接
3. 报告给用户（⚠️ 标注），并区分两类：
   - **指向概念的悬空链接** —— `[[概念名]]` 可能是有意留待将来补写，不算错误
   - **真断链** —— 目标笔记确曾存在（可对照历史名称或别名）
4. **不自动创建缺失文件**

> CLI 不可用时的降级：用 `obsidian search` 或文件系统检索核对目标文件是否存在。
> 注意短名解析规则 —— 全库文件名唯一即可命中，不必拼全路径。

### Step 5 · 更新 index.md

**`index.md` 定位**：用户用的**精选入口**（非全量索引），只收录长期重要、高频和当前推进中的内容，不追求完整。全量导航由 `知识库总索引.md` 承担（Dataview 自动生成）。

1. 读根目录 `index.md`
2. 检查日志提及的笔记是否已收录
3. 未收录的先判断是否满足「长期重要 / 高频 / 当前推进」门槛
4. 满足门槛的按**归属映射**（见 `vault-spec.md`）插入对应板块，保持现有格式（`- [[笔记名]] — 描述`）与缩进
5. **不收录** `0_Inbox/Clippings/`（index.md 维护原则明确排除）

> 新增条目时先报告将插入的板块与条目；批量新增（≥3 条）先等用户确认。

### Step 6 · 变更摘要

```
📋 知识库更新完成 — YYYY-MM-DD

✅ Frontmatter 补全：项目=[xxx, yyy]，tags=[标定, 缺陷检测]，总结="..."
📋 任务快照：延锋座椅检测项目（进行中 2 / 待开始 1 / 已完成 1）
📝 项目进度：由 Dataview 自动查询，无需写入
⚠️ 失效链接：[[不存在的笔记]]
⚠️ 项目名校验：项目X 不在 Project Manager 中
📝 index.md：新增 N 条索引（已按收录门槛过滤）
```

## 独立触发功能

不跟随每日更新，需用户明确触发。

### A. 交叉引用发现

触发词："交叉引用"、"知识发现"。**只建议，不自动添加链接。**

1. **提取技术关键词** —— 从日志 `# 工作记录` 提及的项目出发，读 `4_项目/{项目名}/_tasks/_others/项目总览.md` 的 `## 方案记录` 段落，提取技术关键词（如"手眼标定"、"SVD"、"3D匹配"、"点云分割"）
2. **搜索理论知识库** —— 在 `3_工作/工作知识库/5_理论知识/` 下搜索匹配的目录或笔记
3. **对比现有链接** —— 对照项目总览 `## 相关文档` 中已有链接，过滤已存在的
4. **输出**：

```
🔗 交叉引用建议

[[延锋座椅检测项目|延锋座椅检测]]：
  → 提到"深度图处理" → [[深度图处理技巧]]（建议链接）
  → 提到"SVM分类" → [[SVM原理与应用]]（建议链接）
```

### B. 项目活跃度检查

每次知识库更新时顺带执行，**纯诊断，不修改文件**。

**扫描范围**：`4_项目/{项目名}/{项目名}.md` 且 `pm-project: true` 的项目。

**状态判定**：

```
最后活动日期 = max( 日志中最近一次提及该项目的日期 , 项目 updatedAt )
if 无任何日志提及 and updatedAt 久远 → 报告"无法判定活跃度"
elif 最后活动日期 > 30 天前 → 🔴 严重停滞
elif > 14 天前           → 🟡 需关注
else                     → ✅ 正常
```

日志提及的判定口径：`1_日志/` 中 `## [[项目名]]` 段落，或 frontmatter `项目` 字段包含该项目名。

**输出**（纯文本，不写文件）：

```
📊 项目活跃度检查 — YYYY-MM-DD

✅ 正常 (≤14天): 延锋座椅检测项目 (2天前)
🟡 关注 (15-30天): 大3D项目支持 (22天前)
🔴 停滞 (>30天): 柔性点检框架项目 (49天前)
💤 无法判定: 项目X（无日志提及）
```

**边界**：全部正常 → 简化为「✅ 所有项目活跃度正常」；归档项目不纳入检查。

### C. 健康看板扫描

触发词："健康看板扫描"、"健康检查"。

> **与「知识库体检」的区别**：那个是**分析层**（`vault-audit.md`），全库深度分析、派并行子代理、出 HTML 报告，重。
> 这个是**运维层**的轻量扫描，基于 Dashboard 已有维度，纯文本输出。

基于 `9_系统/Dashboard/知识库健康度.md` 的既有检查维度执行扫描：

- 缺 `总结` / 缺 `tags` 的笔记
- 孤立笔记
- 最近修改情况

输出报告 + 修复建议，**但不自动修改** —— 用户确认后才动手。

## 边界情况

| 情况 | 处理 |
|---|---|
| 用户指定日期（"更新 6 月 1 日的知识库"） | 处理 `1_日志/YYYY/YYYY-06-01.md` |
| 日志不存在 | 告知用户该日期日志不存在 |
| Frontmatter 已完整 | 跳过 Step 2，报告「无需补全」 |
| 正文无 wikilink | 跳过 Step 3、Step 4，报告「正文中无笔记链接」 |
| 项目不在 pm 中 | Step 3 报告快照跳过并提示，不写任何东西 |
| pm 任务文件缺失 | 报告「无法读取任务状态」，继续后续步骤 |
| 项目已归档 | 不写进度、不纳入活跃度检查 |
| 批量更新（"更新最近一周的知识库"） | 逐日执行 Step 1–5，不含活跃度检查 |
| 日期格式 | `日期` 统一为无引号 `YYYY-MM-DD`，读取时兼容带引号写法 |

## 注意事项

- **只改 frontmatter 与 `index.md`**，不修改日志正文
- **`4_项目/` 下 pm 管控文件完全只读**；`_tasks/_others/` 下手动文档也仅建议、不自动写

- LaTeX 行内公式 `$` 与内容间不留空格
- wikilink 用短名格式 `[[笔记名]]`
- 新增 index.md 条目时保持现有格式与缩进（`- [[笔记名]] — 描述`）
- 任务管理在 Project Manager 插件中操作，skill 不创建 / 修改任务
- 知识笔记的 tags 用 `协作约定.md` §4 封闭词表；每日记录的 tags 允许技术域 + 个人域两套
